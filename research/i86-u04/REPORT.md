## State machine (positive pipeline, 14/14 PASS)

`absent → PENDING_CONSENT → CONSENTED → ACQUIRING → HASH_VERIFIED → INSTALLED → READY`

- **P1 consent gate**: without explicit consent → typed `CONSENT_REQUIRED`;
  zero network calls, zero fs writes, zero journal lines.
- **P2 real acquisition**: genuine download from github.com (redirect hop
  pinned: github.com → release-assets.githubusercontent.com, both on the
  catalog's approved-host allowlist, `fetch redirect:'manual'` at every hop),
  whole-artifact SHA-256 + size verified, native handle-relative extraction
  with per-entry SHA identity, identity snapshot (NT FileId + content hash)
  taken on the final roots, **atomic activation by one rename** (the provider
  root never exists partially), 5-phase journal per actionId
  (RECEIVED→VALIDATED→EXEC_START→EXEC_DONE→RECEIPT_WRITTEN).
- **P3 independent action authorization + oracle**: download consent does NOT
  confer run rights — without a task authorization record the task refuses
  typed (`TASK_NOT_AUTHORIZED`), expired grants refuse typed, and only the
  authorized run executes. The task ran `rg` by its **absolute verified path**
  over a 6-file fixture; the oracle re-computed the expected match set with a
  plain node line-scan and compared multisets — 57/57 lines, `rg --version`
  = ripgrep 14.1.1 (rev 4649aa9700). Exit codes are treated as transport facts.
- **P4 removal leg**: user canary inside the provider root → effect-time scope
  exclusivity refusal names the canary, zero deletions, provider retained;
  planted NTFS junction inside the root → native identity-pinned removal
  refuses (no cascade into the download root, junction sentinel untouched);
  after the human resolves the foreign content, removal by install-time NT
  identity deletes exactly the owned trees while an outside sentinel survives;
  unit-level `removeManifestEntries` case proves deepest-first, empty-dir-only
  semantics (recorded dir holding a canary is RETAINED).
- **P5 cache fill via local origin**: origin request count = 1; READY; oracle
  re-verified on origin-served bytes.
- **P6a cache replay (origin up)**: content-addressed cache (keyed by artifact
  SHA, not URL) → **origin request delta = 0**, READY.
- **P6b offline replay (origin dead)**: port probed dead (ECONNREFUSED) →
  READY from the verified cache; zero network possible.
- **P7 interrupt/restart reconcile**: torn journal
  (`MAY_HAVE_EXECUTED_UNCERTAIN` via v0.1 `classifyFromJournal`) + a
  half-written staging file → reconciliation purges staging, fresh attempt
  completes READY; at no point does a half-activated provider root exist.

## Coverage and honest limits

- Catalog trust is pilot-grade: one curator key, in-repo trust root, `_tmp`
  private key. No key ceremony, rotation infra, or persistence of
  grants/consents beyond JSON files.
- The download transport covers HTTPS with manual redirect pinning; no
  resumable/partial download, no signature-of-the-vendor verification beyond
  the artifact digest (ripgrep's release is not Authenticode-verified here —
  the catalog digest is the pin, which is exactly the U04 trust model).
- n6 compiles its hostile rg.exe with the stock .NET Framework csc.exe; the
  DLL-side hijack case is covered for sharp (S5), while for rg the exe-side
  PATH/CWD planting is covered (rg is a static exe with no external DLLs).
- Concurrent-acquire serialization is same-host (in-process mutex + exclusive
  lock directory); no multi-machine locking claim.
- The friendly sharp API was bound to the acquired binding through a
  Module._load hook rather than physical module-resolution redirection; the
  binding bytes that executed are the acquired bytes (proven by direct require
  + digest), but the JS wrapper files still came from the store.
- Worker crash leg covers a cooperative process.exit crash, not a hard native
  access-violation; no file locks exist to clean (verified by residue scan).
