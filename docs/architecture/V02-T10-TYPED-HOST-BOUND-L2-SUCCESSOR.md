## 2. Concrete wire and parsing contract (proposed protocol)

**Public protocol**: SHUN_T10_SEMANTIC_V1, one static pinned English instruction (interprets CN/EN user goal without revealing host identity) and exactly the previously previewed user goal text; a model-generated strict JSON object with EXACT keys:
    { "protocol": "SHUN_T10_SEMANTIC_V1", "intent": "STORAGE_READ_ONLY_DIAGNOSIS", "decision": "READY" }

The only acceptable protocol value is SHUN_T10_SEMANTIC_V1. Allowed intent values are STORAGE_READ_ONLY_DIAGNOSIS, STORAGE_CACHE_CLEANUP_CANDIDATE, and UNRESOLVED. Allowed decision values are READY and NEEDS_CLARIFICATION; force NOT_READY whenever intent=UNRESOLVED or decision=NEEDS_CLARIFICATION, or when the Host cannot prove objective compatibility. No model-origin path, task ID, policy, tool name, command, script, approval, provenance or arbitrary object list is admissible. Reject unparseable or markdown-wrapped JSON, duplicate/extra fields, unsupported enum, unbounded body or nonterminal response. The parser is strict and deterministic; no LLM repair/retry for invalid JSON.

This closed enum only establishes *candidate semantics*; it does not authorize cleanup. In particular, a model suggesting CACHE_CLEANUP_CANDIDATE for an original read-only diagnosis produces a read-only recommendation or NOT_READY, never a cleanup task. If a cleaned schema or model text includes an executable string, it has no action authority.

**Host binding:** use the immutable original host-selected GoalRequest taskId, goal, objects, constraints, privacy/environment policy, verification intent and observed registry currentness. Host must check the typed model intent against registered C003 capability and the original literal/verified user intent. Preserve existing strict GoalProposalSchema and deterministic remotePlannerAdapter / interpretGoalViaPlanner for the final constructed proposal; explicitly define a small adapter from model-semantic-fragment to Host-private contract, do NOT rewrite the entire Resolver or change contracts merely to fit the LLM output. Where existing #213 helper requires model-authored full GoalProposal, it cannot be fed the fragment without a separate trusted Host adapter and an exact independent review of that interface. No fabricated model evidence: bind only actual trusted transport attempt identifiers, model ID as observed, with immutable model revision UNKNOWN where unproven.

### 3.1 Verified native compatibility and preferred minimum path

A source-level inspection at this version pin found the actual Rust broker in apps/control-api/native/broker/src/consent.rs: validate_request reads projectionJson, requires exactly **five** keys (destination, providerId, modelId, disclosureCategories, goalText), exactly the existing GOAL_TEXT category, a valid goalText length and the SHA256 of those exact UTF-8 projection bytes. It will reject an added requestBodySha256, protocolRevision or extra field today. Therefore a new two-message system+user request with an unchanged old GOAL_TEXT disclosure is **not permitted**.

**Preferred first experiment (no native ABI expansion):** use the existing, byte-checked *single user message* only. Construct a small, fixed public SHUN_T10_SEMANTIC_V1 response instruction as a deterministic **part of the same goalText string** that the user explicitly sees and approves in the UI. The original user goal appears verbatim at the beginning of this framed text (to preserve the Broker's short visible goal preview), with a bounded fixed format instruction after a deterministic delimiter. The exact same framed string is input to buildDeepSeekGoalDisclosure, native C02 projectionJson and TrustedDeepSeekTransport.invoke, so the frozen exactRequestBytes serializer still sends one messages[0].content exactly equal to the approved goalText. There are NO new request JSON properties, tools, response_format controls, system messages or undisclosed host-private fields. Keep existing max_tokens/stream/thinking/model values and old C02 signature/currentness; treat fixed instruction text as **new disclosed bytes**, not invisible model setup.

**Required data ownership:** originalHumanGoal and framedGoalText are different immutable Host-owned values; the model receives only the framed string while the Host retains the original for semantic comparison. Browser never gets to supply a claimed Host-approved frame/protocol as authorization. The Host builds preview AND actual invocation from the SAME canonical framing function and verifies framed bytes, approvedProjectionSha256, token ceilings and nonce immediately before send. Reject a user goal that plus protocol framing exceeds the present 8192-character native limit (do not truncate). The static protocol is fixed at version compile time and changes require fresh exact-source review and newly approved disclosure. Do not log raw framed/private goal. C02 native dialog displays only a short prefix, so the separate full browser disclosure preview and an unambiguous indication that formatting instructions are included must be confirmed by real Windows UX validation; a short prefix alone is not evidence the human saw all outbound bytes.

**Acceptance and fallback:** a real CN and EN DeepSeek response must successfully produce the exact strict semantic V1 JSON; if the model does not obey a user-role-only formatting instruction, return NOT_READY/REMOTE_REFUSED and keep zero execution. **Do not** silently upgrade to an undisclosed system message. Only if real acceptance shows this minimum framing insufficient should Architecture Owner review an explicit separately consented projection/ABI successor: new exact requestBodySha256 or protocolRevision fields would require Rust five-key whitelist, C02 preview and signed projection, TS schema/transport and replay/negative tests as one bounded T01/C02 source claim.
