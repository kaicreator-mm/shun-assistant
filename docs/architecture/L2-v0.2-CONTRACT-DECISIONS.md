## 2. LLM trust contract and LOCAL-only source binding

```ts
type ModelTrust = 'REMOTE_USER_OPT_IN' | 'LOCAL_HOST_ATTESTED' | 'UNAVAILABLE';
type PlannerOutcome =
  | { status: 'PROPOSAL'; goalProposal: unknown; modelReceiptId: string; trust: ModelTrust }
  | { status: 'NEEDS_CLARIFICATION'; question: string }
  | { status: 'UNAVAILABLE' | 'POLICY_BLOCKED'; reasonCode: string };

type ModelRequestPrivacy = {
  disclosureConsentRef?: string; // only for the remote adapter, no raw secrets in logs
  allowedFields: readonly string[]; // minimal, redact by default
  localOnly: boolean; offline: boolean; tokenLimit: number; timeoutMs: number;
};
```

- A `LOCAL_HOST_ATTESTED` outcome can only originate from a trusted host-owned adapter whose process identity, local inference engine, egress policy and tests establish true local behavior. Caller-supplied loopback, model name and privacy flags are not proofs; a reverse proxy pointing remotely fails. #85's real hostile-seam probes PASS for *refusals only*, while actual local inference and enforced process egress are **BLOCKED** because the host had no local model and its non-elevated firewall/AppContainer probe did not establish isolation. L2 MUST NOT treat this as LOCAL support.
- `REMOTE_USER_OPT_IN` path is separate from `LOCAL_ONLY`, OFFLINE and no-disclosure policy; unauthorized remote attempt produces **zero requests**. Actual remote API availability is not a LOCAL security substitute.
- **Mandatory PRE-PLANNER CURRENTNESS GATE:** before any outbound **or local** LLM request, obtain host-owned current registry/capability/policy/privacy/disclosure evidence, validate against trustworthy currentness authority and proposed-minimal-data projection. Missing, expired, inconsistent or unattested currentness → typed `PLANNER_UNAVAILABLE/POLICY_BLOCKED` with **zero model invocations / zero outbound disclosure**. Host-attested LOCAL also requires separate OS network/identity proof, independent of registry currentness. After the LLM response, still run the old deterministic `resolveGoal` gate and ActionController; precheck is not authorization. #85 host proof found that v0.1 allows an eligible REMOTE model invocation before `resolveGoal` rejects stale registry state; this is a new v0.2 negative acceptance, not retroactively a v0.1 fix claim.
- Store only minimized model request metadata and an untrusted proposal hash; model cannot select grant keys, trusted providers, Windows target scopes or arbitrary tool paths.

## 3. Immutable Recipe representation + execution route

```ts
type RepresentationKind = 'SOURCE_JS_TS' | 'TYPED_ACTION_GRAPH' | 'COMPILED_JS';
type RecipeVersion = {
  recipeId: string; revision: string;
  manifest: readonly { kind: RepresentationKind; sha256: string; required: true }[];
  executableIdentityDigest: string; // hashes immutable revision+ALL representation digests+declared effects+verifier identity
  parameterSchemaRef: string; verifierId: string; verifierRevision: string;
  declaredCapabilityIds: readonly string[];
  approvedProviderBindingRefs: readonly string[];
  lifecycle: 'CANDIDATE' | 'VERIFIED' | 'ENABLED' | 'STALE' | 'REVOKED' | 'BLOCKED';
};
type RunDisposition =
  | 'EXACT_REUSE' | 'REBIND_RECHECK' | 'REVALIDATE_FACTS_ONLY'
  | 'NEW_REVISION_REQUIRED' | 'BLOCK';
```

- Versioned source/graph/compiled artifacts are **independently rehashed** for every exact replay. A changed graph with same JS source, or changed JS source with same graph, is **BLOCK**. User-intentional edit uses a **new** recipe revision, new verification and independent user promotion; old authority never migrates.
- JS/TS may be inspected, saved, transformed by a **reviewed closed-world compiler into typed action data**, or executed as bounded trusted code. **Untrusted arbitrary JS is not executed in-process**; Node `vm`/permission flags/AST scans do not establish an OS sandbox. No unrestricted `powershell -Command`.
- Normal user replays do **not** invoke the LLM if the Recipe is exact/current. New parameters rebind checked scopes, re-plan and grant afresh. Every high-risk effect gets user-visible per-task approval and independent outcome verification. Effects journaled before invocation; UNCERTAIN recovery cannot blind retry.

## 4. Provider catalog and trust bootstrap (no third layer)

```ts
type ApprovedProviderArtifact = {
  catalogRevision: string; providerId: string; bindingId: string;
  origin: string; exactVersion: string; artifactSha256: string;
  expectedWindowsArch: 'x64' | 'arm64'; nodeAbi?: string;
  dependencyDigests: readonly string[]; artifactKind: 'CLI' | 'NODE_NATIVE_ADDON';
  capabilityIds: readonly string[]; scopedVerifierId: string;
};
type Availability =
  | 'READY' | 'ABSENT' | 'ACQUIRE_NEEDS_CONSENT'
  | 'OFFLINE' | 'TRUST_FAILED' | 'ABI_MISMATCH'
  | 'RECOVERY_UNCERTAIN' | 'REVOKED';
```

- **Trust root is installed with Core and independent of download**. Signed or authenticated catalog + pinned exact artifact hash is mandatory; a checked hash calculated from the just-downloaded untrusted blob, without an authenticated reference, proves nothing. Authenticode may add provenance but is **not** automatically available for unsigned OSS binaries and cannot be silently asserted. Every executable/addon, dependency and native DLL has to be covered by policy.
- A user agreeing to download **cannot override invalid trust**. Acquisition (network/storage) consent and arbitrary user-file mutation consent are separate. #86 reports a bounded positive Windows manifest/JIT/Sharp native child-worker proof with strict SHA, but the friendly Sharp API used a test-only `Module._load` hook: **do not adopt unrestricted hook/import interception as the production trust boundary**. Prefer explicit, verified worker entrypoints with pinned binary/module paths and dependency closure. On first use, stage within Shun-owned root → verify catalog/artifact/dependency/OS/ABI → atomic publication → typed effect execution and oracle; offline absence never blocks native system reports.
- Caches are content-identity keyed, restart-resolvable, revocable, and leased while used. No raw `npm install`, user-chosen DLL, external FFI function name, automatic marketplace, code-signing trust rooted in a just-downloaded manifest or in-process hot reload requirement.
- A native `sharp` addon is separate from the `fd/ripgrep` CLI proof: CLI PASS does not assert addon/Node ABI PASS. Native addon direct import must be at an independently verified trust/worker boundary before execution. `node-api-dotnet`, `dynwinrt`, `Koffi` and `node-win32-api` remain outside v0.2.

### 4.1 Durable state and portable path boundary — U05 adoption

- #87 Windows 11 Pro UAC-filtered medium-integrity test used bundled Node v24.21.0 and an esbuild core with real `simulated:false` C003 R2 clean-up, verified receipts and crash recovery. **Architectural feasibility of portable local-disk core is accepted**, not the release of a real system-inventory UI, full ordinary-user installation or Home+Pro matrix.
- SQLite `journal_mode=WAL` is **not safely supported on arbitrary UNC/SMB or WSL Plan 9 network shares** in this design. Installer/first-run places `ShunStore`, registry/issuance currentness, journals and credential-bearing state only on pinned local fixed-disk managed directories. External user files/selected workspaces may be UNC **only with separate scoped path/capability proof**; never promote an arbitrary network path to authoritative state. If state path is remote/ambiguous, fail closed with an actionable user-facing error, no silent fallback or secret copy.
- For true non-admin portability and cold boot, validate on **true standard-user account** in later T09/T11, not just a filtered admin token. Per-user keys and restrictive ACLs need independent installer verification. C003 as a real task is a positive baseline; CPU/process/startup inventory UI remains unimplemented and is separately owned by T06/T08.
- #85 outcome remains LOCAL_BLOCKED despite identification of a probable research-harness attribute constant bug; corrected research-only AppContainer launcher `research/i85-appcontainer-attribute-fix@62e5dcbf36ec92394e1385c4dfed5c96d8c57362` still needs a real Windows retest and provisioned local model. #86 ripgrep/Sharp architecture-pilot PASS is now durably published as `task/i86-u04-zc@ae4d8c04df16c0e17d77e745b88c4d13b620b0fe` (tree `5f3b559e22c11333211b11ac54b30efa4cf49ced`) and #86 is CLOSED; full v0.2 loader and hostile native crash remain later validation.
