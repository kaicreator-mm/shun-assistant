## 1. Exact change and what remains required

This scoped clarification replaces **only** the impossible expectation that a remote model can author trustworthy complete GoalProposal fields for host-private values it never received. The model must still make a **genuine, nontrivial, typed semantic planning decision** using the actual consented Chinese or English goal. The trusted Host then binds the model's typed semantic data to an immutable, independently selected original GoalRequest, registry and currentness, builds a validated GoalProposal for review, and never accepts model-issued grant or execution authority. Plain advisory prose cannot be counted as a typed model proposal PASS.

P0 still requires genuine DeepSeek Flash API positive CN and EN requests, signed private Win32 C02 consent for the exact outbound bytes, privacy/zero-call and cost gates, strict proposal validation, ActionController exact-planHash user approval for an actual allowed effect, independent Windows poststate and durable receipt. One real HTTP 200 or a simulated PlannerPort is not a full acceptance journey. Model refusal, unavailable model, ambiguous intent, hallucinated action or extra disclosure must fail closed to NOT_READY or refusal, not silently switch capabilities.

## 2. Minimum model-authoritative fields

Under B, model output may contain only an explicitly versioned semantic fragment, such as:
    { "protocol": "SHUN_T10_SEMANTIC_V1", "intent": "STORAGE_READ_ONLY_DIAGNOSIS", "decision": "READY" }

The closed, host-registered intent enum for the initial C003 lane is:
- STORAGE_READ_ONLY_DIAGNOSIS — read-only analysis or explanation, never deletion.
- STORAGE_CACHE_CLEANUP_CANDIDATE — only a recommendation that cleanup might be useful, not consent to perform it.
- UNRESOLVED — must not become an executable action.

A deterministic strict parser must reject unsupported protocols, extra keys, malformed JSON, unsupported values, policy/host fields, paths, tool requests, prompts that attempt to issue commands and model-provided grants; reject contradictions or ambiguities rather than guessing. Any model-provided explanation is optional non-authoritative display text with a fixed small byte/character cap, escaped as text. A genuine typed enum/decision must be observed from actual DeepSeek responses in both languages, not synthesized by a test fixture.

## 3. Trust ownership and refusal

The Host **solely** supplies taskId, object identity and workspace root, constraints, privacy and environment policy, selected allowed capability, registry/source revision, actual model-attempt provenance, currentness, approval and result verification. These are never accepted from a model, browser form or external response. The Host must not upgrade an original inspect-only or RETAIN/readOnly intention to cleanup, even when the model suggests cleanup. A typed recommendation can be shown to the user, but cannot alter an immutable GoalRequest's scope.

The existing Win32 broker consent authorizes only one separately displayed DeepSeek disclosure. It is **not local operation consent** and must not be reused as a C003 approval. A local cleanup, if chosen, is a visibly separate human-directed local task in the trusted application, must undergo the existing independent exact-planHash approval and currentness check in ActionController, then independently verified poststate. Do not claim cryptographic same-human provenance across cloud response and local selection unless a separately reviewed OS principal/session gesture actually proves it. Ordinary loopback JSON/Origin and bearer IDs do not.

No automatic action, shell, generated script, arbitrary Provider invocation, elevation, silent retry after UNKNOWN_COST or unsupported capability is authorized by this Product decision. The accepted bounded #213/#220 host-only helpers retain their exact reviewed constraints; they are not proof that current GOAL_TEXT-only production integration already accepts a real model typed fragment.

## 4. Egress and consent promise

Keep **minimum actual user-private disclosure**: existing goal text only, with no additional host-private paths, file/process contents, policy, token, SID/session, user credential or registry source facts. A fixed public protocol instruction or public strict output schema may be added only through a separately reviewed T01/C02 request contract. Every changed outbound byte (static system prompt, user message, response options and generation limits, including model/destination and protocol revision) must be visible in or cryptographically bound to the exact pre-send disclosure preview and native broker-approved digest **before** HTTPS. If the current broker projection whitelist cannot attest the revised wire shape, the implementation is BLOCK until a narrow separately authorized ABI successor is independently reviewed. Never hide a prompt or add metadata after approval.

Existing LOCAL_ONLY, offline, FORBIDDEN, no private OS consent, stale host/source authority, prohibited disclosure, missing key, cost ceiling, exhausted max calls and transport failures remain fail-closed; ambiguous send retains UNKNOWN_COST and is never blindly retried. Real model usage/cost remains UNKNOWN until credible settlement; never fabricate model revision or amount.

## 5. Acceptance matrix and immutable evidence

1. Exact source static protocol/schema, exact consented final HTTP bytes and native C02 projection/digest/currentness match, including negative tamper and no hidden extra prompt.
2. Real separately consented CN and EN DeepSeek Flash responses: genuine strict semantic fragment -> deterministic host-bound typed GoalProposal when compatible, or explicit NOT_READY. Forged host facts/model commands/unknown enum/changed currentness -> zero grant, zero task.
3. User-original read-only, RETAIN, missing object, changed workspace/path/policy and forged typed fields cannot promote to cache cleanup; under ambiguity or mismatch only clarification/read-only.
4. If the user separately elects fixed local C003 cleanup, the trusted local task's exact plan preview/planHash is distinctly approved or declined. Negative plan drift/decline/replay, post-authority revocation and invalid source/currentness have zero unauthorized effects. Effectful positive must use actual Win32/RealStorage controller with independent before/after verification. A synthetic backend is not Windows proof.
5. T09 existing physical Recipe evidence may be reused at exact compatible identities. T10 must close real CN historical 503 and EN NOT_RUN without exceeding new user-approved paid-call budget; T11 Home/Pro delivery, verified first executable, Full/Hidden and RQ remain mandatory.
